# Issues

Concrete implementation-problem records: a specific problem, its root cause, the
fix, and how it was verified. Use this when the detail is worth keeping but does
not belong in [architecture](../architecture/index.md),
[learning](../learning/README.md), or [practices](../practices/README.md).

This is for repository engineering notes, not the Paperclip control-plane issue
tracker (those live in the product database and are managed via the `paperclip`
skill).

Naming: `YYYY-MM-DD-slug.md`, or `YYYY-MM-DD-slug/` with `index.md` if it grows.
Redact private identifiers to placeholders (see
[repo-records](../../references/repo-records.md#issues)).
